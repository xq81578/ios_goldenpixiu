# 1.4.0

## New feature: Channels

Channels (previously known as "id") are a new way to improve your event tracking and debugging capabilities. By using `SetChannel()` during event emission or marking event classes with `[DefaultChannel]`, you can better organize events and simplify log analysis.

- Log Tool doesn't show the "id" anymore, but the channel at the beginning of each raised event.

- Added `_channel` and `SetChannel()` to the GameEvent class

- Added attribute `[DefaultChannel]` to use in event classes. (SetChannel overrides it)

- Added channel filter in Log Tool.

- Added example on how to use channels.

> Channels DOES NOT affect in any way emission / subscription of events. Workflow remains the same.


## General

- Now filters applied in the Log Tool are saved in `EditorPrefs`

- Exposed execution ms limit (default 50ms, if total execution time of an event is greater a warning will be shown in the console)



## Deprecations

- `_id` and `SetId()` are now marked as Obsolete and will be removed in the future. Please migrate to `_channel` and `SetChannel()`



## Removed deprecated methods

- Removed `StopPropagation()` marked as obsolete in 1.1.1. Use instead StopPropagation(canceller)

- Removed `PublishShared()` marked as obsolete in 1.1.1. Use instead `.Shared().Publish()` from the event instance.
