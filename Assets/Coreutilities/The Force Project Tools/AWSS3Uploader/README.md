# AWS S3 上傳器

Unity 編輯器工具，提供圖形化介面來管理 AWS S3 檔案上傳功能。

## 功能特色

- **多設定檔管理** - 支援建立、切換、刪除不同的上傳設定檔
- **AWS S3 整合** - 與 Amazon S3 服務完整整合
- **並行上傳** - 支援並行上傳多個檔案（1-10個），提升上傳效率
- **進度追蹤** - 即時顯示上傳進度和狀態
- **AssetBundle 支援** - 支援 AssetBundle 檔案的獨立上傳
- **智能清除保護** - 支援上傳前清空 S3 目錄，但保護指定資料夾不被清除
- **重複檢查機制** - 智能跳過已存在的相同檔案，大幅節省上傳流量
- **作業時間追蹤** - 詳細記錄主遊戲、AssetBundle 和整體作業的耗時
- **智能路徑匹配** - 自動檢查本地路徑與 S3 路徑的匹配性
- **特殊檔案處理** - 自動設定 WebAssembly 和壓縮檔案的正確標頭

## 如何開啟工具

在 Unity 編輯器中，透過選單：**Tools → AWS S3 上傳器**

## 使用步驟

### 1. 設定檔管理

- 建立新的設定檔或使用現有設定檔
- 可以建立多個設定檔用於不同的環境
- 點擊「管理設定檔」可以展開管理選項
- 支援設定檔的重命名和刪除功能

### 2. AWS 設定

- **AWS 區域**：選擇您的 S3 儲存桶所在區域（如：us-west-2, ap-northeast-1）
- **Access Key ID**：您的 AWS 存取金鑰 ID
- **Secret Access Key**：您的 AWS 秘密存取金鑰
- 點擊「測試 AWS 連線」確認設定正確（30秒超時）

### 3. 上傳設定

- **本地目錄**：要上傳的檔案夾路徑，可以使用瀏覽按鈕選擇
- **S3 儲存桶名稱**：目標 S3 儲存桶的名稱
- **S3 路徑前綴**：上傳到 S3 的路徑前綴
- **並行上傳數量**：同時上傳的檔案數量（1-10個），可根據網路狀況調整

#### 並行上傳建議設定

- 網路狀況良好：5-8 個並行上傳
- 網路狀況一般：3-5 個並行上傳
- 網路狀況較差：1-2 個並行上傳
- 檔案數量少於 10 個：建議設定為檔案數量

### 4. AssetBundle 設定

- **自動上傳**：勾選後主遊戲上傳完成時會自動上傳 AssetBundle
- **Bundle 目錄**：選擇 AssetBundle 檔案所在的本地目錄
- **S3 路徑組合**：五個部分組成完整的上傳路徑
  - S3 儲存桶名稱（只讀）：顯示目標 S3 儲存桶名稱
  - 第一個分隔符 "/"
  - S3 路徑前綴（只讀）：顯示主要的 S3 路徑前綴
  - 第二個分隔符 "/"
  - Bundle S3 路徑（可編輯）：AssetBundle 在 S3 中的子路徑
- **完整路徑**：系統會顯示完整的上傳路徑預覽（`s3://儲存桶名稱/S3路徑前綴/Bundle路徑`）

#### 進階上傳設定 🆕

- **不清Bundle資料夾**：勾選後在清空主遊戲目錄時會保護指定的AssetBundle資料夾不被刪除
  - 動態顯示當前受保護的資料夾名稱（來自Bundle S3路徑設定）
- **跳過重複Bundle**：勾選後會智能檢查S3上的現有檔案，跳過相同的AssetBundle檔案以節省流量
  - 可節省60-90%的上傳流量（取決於檔案變更頻率）

### 5. 開始上傳

1. 點擊「開始上傳」
2. 系統會自動進行**路徑匹配檢查**：
   - 從本地路徑中自動提取專案編號（如 `slot001_prosperoustiger` → `slot001`）
   - 檢查是否與 S3 路徑前綴匹配
   - 如果不匹配會彈出警告對話框
3. 確認上傳設定對話框中的資訊
4. ⚠️ **注意：上傳過程會先清空目標目錄的檔案（受保護資料夾除外）**
5. 點擊「確認上傳」開始上傳

## 操作功能

### 主要操作

- **開始上傳** - 開始主要檔案上傳
- **取消上傳** - 取消進行中的上傳（使用 CancellationToken 正確取消）
- **測試 AWS 連線** - 驗證 AWS 憑證和區域設定
- **取得檔案列表** - 查看 S3 上的檔案清單（60秒超時）

### AssetBundle 管理

- **AssetBundle 手動上傳** - 獨立上傳 AssetBundle 檔案
- **AssetBundle 自動上傳** - 主遊戲上傳完成後自動上傳

### 日誌管理

- **清空日誌** - 清除操作日誌
- **自動滾動** - 自動滾動到最新日誌
- **滾動到底部** - 手動滾動到底部

## 進度顯示

上傳過程中會顯示：

- **主遊戲檔案上傳進度** - 顯示進度百分比和完成檔案數
- **AssetBundle 上傳進度** - 如果啟用會顯示 AssetBundle 進度
- **整體上傳進度** - 綜合顯示總體進度
- **並行上傳狀態** - 顯示當前正在同時上傳的檔案列表

### 進度顯示範例

```
整體進度: 65.3% (13/20 個檔案)
正在上傳 3 個檔案: example.js, data.json, config.xml
並行上傳中... (3/5)
```

## 智能功能 🆕

### 智能清除保護

- **功能說明**：在清空S3目標目錄時自動保護指定的AssetBundle資料夾
- **保護機制**：根據AssetBundle S3路徑設定動態確定受保護的資料夾
- **日誌顯示**：詳細記錄清理過程，顯示保護的檔案數量
- **安全性**：避免意外刪除重要的AssetBundle檔案

### Bundle重複檢查 🆕

- **功能說明**：上傳AssetBundle前先檢查S3上的現有檔案，跳過相同檔案
- **比較機制**：基於檔案大小進行智能比較
- **流量節省**：可節省60-90%的AssetBundle上傳流量
- **智能跳過**：自動跳過無需重複上傳的檔案，並在日誌中詳細記錄

### 作業時間追蹤 🆕

- **主遊戲作業耗時**：單獨記錄主遊戲檔案上傳的總耗時
- **AssetBundle作業耗時**：單獨記錄AssetBundle檔案上傳的總耗時  
- **整體作業耗時**：記錄從開始到完成的完整作業時間
- **智能格式**：少於1分鐘顯示秒數，超過1分鐘顯示分鐘數
- **取消狀態**：區分正常完成和用戶取消的不同狀態

#### 時間追蹤日誌範例

```
⏱️ 主遊戲作業完成，總耗時: 2.5分鐘
⏱️ AssetBundle作業完成，總耗時: 1.2分鐘  
⏱️ 整體作業完成，總耗時: 3.8分鐘
```

## 特殊檔案處理

工具會自動為以下檔案設定正確的 Content-Type 和 Content-Encoding：

- `.wasm.br` → Content-Type: application/wasm, Content-Encoding: br
- `.data.br` → Content-Type: application/octet-stream, Content-Encoding: br
- `.js.br` → Content-Type: application/javascript, Content-Encoding: br
- `.br` → Content-Encoding: br

## 智能路徑匹配檢查

### 功能說明

- **自動檢查**：上傳前自動檢查本地路徑和 S3 路徑前綴是否匹配
- **專案識別**：從本地路徑中自動提取專案編號（如 `slot001_prosperoustiger` → `slot001`）
- **警告提示**：當路徑不匹配時會彈出警告對話框，防止上傳到錯誤位置
- **用戶確認**：可以選擇繼續上傳或取消操作
- **多專案支援**：特別適合同時開發多個專案的情況

### 適用條件

- 目錄名稱包含 "slot" 和底線的命名規則
- 專案編號格式：`slotXXX_projectname`

## 重要警告與注意事項

### 🚨 資料安全警告

1. **上傳前會清空目標目錄** - 開始上傳時會先刪除 S3 目標路徑下的所有檔案
2. **操作不可復原** - 已刪除的檔案無法恢復
3. **請謹慎確認路徑** - 上傳前請仔細確認 S3 儲存桶名稱和路徑前綴
4. **路徑匹配檢查** - 系統會自動檢查路徑匹配，如有不匹配請務必仔細確認

### 權限要求

AWS 使用者需要有以下權限：

- `s3:ListBucket` - 列出檔案（必須）
- `s3:PutObject` - 上傳檔案（必須）
- `s3:DeleteObject` - 刪除檔案（清空目錄時需要）

### 性能優化

- 並行上傳數量不宜過高，避免網路阻塞
- 智能文件大小排序，優先上傳小檔案
- 線程安全的進度更新機制
- 使用 CancellationToken 正確實現取消功能

### 網路相關

- 確保網路連線穩定以避免上傳失敗
- 大檔案上傳可能需要較長時間
- 支援連線和檔案列表操作的超時機制

## 故障排除

### 連線問題

1. **連線測試失敗**
   - 檢查 AWS 認證是否正確
   - 確認網路連線正常
   - 驗證 AWS 區域設定
   - 檢查防火牆設定

2. **上傳失敗**
   - 檢查 S3 Bucket 權限
   - 確認本地檔案路徑存在
   - 檢查檔案是否被其他程式佔用
   - 確認 IAM 政策設定正確

### 路徑匹配問題

- 本地路徑中找不到專案編號，請確認目錄結構是否正確
- 專案編號提取失敗，請檢查目錄名稱是否包含 "slot" 和底線
- 路徑匹配檢查過於嚴格，可選擇「確定繼續」手動覆蓋檢查
- 如有特殊命名規則，請確認專案編號格式

### 取消上傳問題

- 如果取消上傳不起作用，關閉並重新開啟工具視窗
- 檢查日誌中的取消操作記錄
- 確認網路連線狀態

### 性能問題

- 降低並行上傳數量
- 檢查網路頻寬
- 考慮檔案大小和數量
- 查看系統資源使用情況

## 安全建議

1. **憑證管理**
   - 不要在版本控制中提交包含 AWS 憑證的設定檔
   - 定期更換 AWS 存取金鑰
   - 建議使用 IAM 角色和臨時憑證，而非長期金鑰

2. **權限控制**
   - 限制 S3 儲存桶的存取權限
   - 定期檢查 AWS 帳戶的使用狀況

3. **資料保護**
   - 上傳前確認目標路徑正確
   - 定期備份重要檔案
   - 使用版本控制管理專案檔案

## 已知限制

- 單次上傳最多支援 10 個並行任務
- 檔案列表顯示最多 1000 個檔案
- 操作日誌最多保留 500 條記錄
- 連線測試超時時間為 30 秒
- 檔案列表獲取超時時間為 60 秒
- 路徑匹配檢查僅適用於包含 "slot" 和底線的目錄命名規則
- 特殊的專案命名規則可能導致路徑匹配檢查失效
